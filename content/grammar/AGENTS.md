# Инструкции Codex — раздел испанской грамматики

Область действия: только отдельный раздел сайта «Грамматика испанского языка» (количество юнитов определяется содержимым каталога). Не распространять задачи на основной курс A0/A1 без явного запроса пользователя.

## Постоянные правила

1. Для **нового юнита по странице учебника** прочитай целиком и применяй **оба** гайда: `docs/grammar/GRAMMAR_UNIT_GUIDE.md` (реестр источника, действующий формат данных, режим ударений, проверки) и `content/grammar/CODEX_GUIDE_SPANISH_GRAMMAR.md` (универсальная методика, обратная связь, итоговая визуальная памятка). Для существенной переработки существующего юнита **также прочитай оба** документа, включая раздел 21 гайда переноса. Для небольших исправлений достаточно относящихся к задаче правил.
2. Работай **строго по одному целевому юниту**; сначала аудит и план, затем реализация, тесты, отчёт. Не переходи к следующему юниту без команды пользователя.
3. Не перерабатывай содержимое других юнитов массово. Общие компоненты можно исправлять с обеспечением обратной совместимости и регрессионными тестами.
4. Грамматическая точность, однозначная проверка ответов и удобство для начинающего важнее косметического разнообразия. Спорные формы проверять по авторитетным нормативным источникам.
5. Для упражнения и мини-проверки — ровно 3 жизни. **После первой же неправильной отправки** сразу показывай правильный ответ, все допустимые альтернативы и объяснение, по возможности причину ошибки; каждая красная отправка расходует 1 жизнь и не даёт зачёта. После третьей ошибки оставайся на вопросе с подробным разбором и добровольными кнопками «Повторить правило» и «Попробовать заново»; из теории можно вернуться к разбору. В нескольких пропусках подсвечивай ошибочные поля. **Простое переписывание уже раскрытого ответа не даёт бесплатного зачёта**; для самостоятельной проверки нужен новый вариант или учитываемая ошибка. Жёлтые ответы засчитываются без ошибки; политика ударений неизменна, текстовые поля имеют `á é í ó ú ü ñ`. Правильные варианты не должны систематически стоять в конце.
6. **Последний учебный экран любого нового или существенно переработанного юнита** — тематическая адаптивная карта-памятка в `summary` («Что запомнить»), по §9.2 универсального гайда: короткие группы/сравнения, точные формы, без повторения всей теории. Используй существующую схему и компоненты. Проверь отображение на узком и широком телефоне, планшете/десктопе, приложи скриншоты в отчёте. Если текущие компоненты не позволяют нужную композицию, покажи ограничение и предложи совместимую отдельную UI-доработку, не нарушая схему.
7. Перед завершением **нового или изменённого юнита** запускай `python -m espanol grammar-lint NN`, сверяй JSON с `content/grammar/schema.json` и `docs/grammar_fields.md`; все ERROR исправлять, каждое WARNING проверять, не считать эвристику доказательством. При работе с данными см. `docs/grammar_lint_guide.md`.
8. **Стиль теории** — «связка → правило → почему → граница» (`docs/grammar/GRAMMAR_UNIT_GUIDE.md`, раздел 6.2, образец — юнит 1). Он обязателен и для новых юнитов, и при просьбе «перепиши теорию юнита N». Для переписывания теории готового юнита — порядок и короткий набор проверок из раздела 21.1: полный `pytest` локально не нужен, он идёт на GitHub при пуше.
9. В конце работы укажи изменённые файлы/подразделы, проверенные сценарии, оставшиеся риски и остановись.

Если в этой папке уже существует `AGENTS.md`, **не заменяй его молча**: вручную объедини совместимые инструкции и разреши конфликты с владельцем проекта.
