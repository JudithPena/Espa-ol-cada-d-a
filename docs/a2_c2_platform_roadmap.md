# Дорожная карта платформы: от A1 к C2

Что в нынешнем движке сайта выдержит рост, что его ограничит и в каком порядке это менять. Педагогические
основания — в [стратегии](a2_c2_curriculum_strategy.md); находки с ID — в [реестре аудита](a0_a1_mythos_issues.md).
Код не менялся: всё ниже — предложения.

## 1. Что масштабируется хорошо (сохранить как есть)

| Возможность | Почему годится и дальше |
|---|---|
| Урок-сценарий в YAML и сборка `espanol/site.py` → данные страницы | автор управляет порядком шагов; формат читаем и проверяем; новые блоки добавляются по одному образцу (`SCENARIO`) |
| Проверка при сборке (`validate`, `espanol/scenario.py`) | ошибки формата не доходят до ученика; сюда же добавляются проверки содержания |
| Ссылки задания `source / rule / skill`, пояснения `mistakes`, замена звука `noaudio` | это и есть модель «задание знает свой контекст»; для длинных источников нужна та же связь |
| Версии уроков (`version`, `P.ver`) | позволяют менять уроки, не стирая прохождение |
| Навыки и повторение по интервалам (`P.skills`) | основа для повторения конструкций на всех уровнях |
| Итоги с порогом (`check: control`) | механизм готов; слабое место — содержание итогов, а не код |
| Движок в `node:vm` для тестов (`tools/site_vm.cjs`), проход в браузере (`tools/site_walk.mjs`), карты слайдов | позволяют проверять новые механики без ручного прохождения |
| Заранее записанная озвучка с постоянными голосами персонажей | качество и предсказуемость; ограничение — три голоса Испании |

## 2. Что ограничит рост — с измерениями

| № | Ограничение | Измерение | Чем грозит |
|---|---|---|---|
| L1 | **Весь сайт — один файл.** | `site/index.html` — 19,4 МБ: книги 13,1 МБ, уроки A0–A1 3,2 МБ (из них картинки слов 2,0 МБ), грамматика 2,5 МБ. Предел файла на Cloudflare Pages — 25 МиБ ([лимиты Pages](https://developers.cloudflare.com/pages/platform/limits)). | до предела осталось около 5 МБ: его исчерпают либо новые книги, либо уровень A2. После этого выкладка сайта перестанет проходить. Каждый ученик уже сейчас скачивает 19 МБ ради одного урока. |
| L2 | **Запись прогресса — одна и целиком.** | 58 КБ после A0–A1 (расчёт); отправка при закрытии страницы отключается после 60 КБ; сервер принимает до 256 КБ (ENG-11) | с A2 прогресс перестанет сохраняться при закрытии вкладки; к B2 запись может перестать приниматься |
| L3 | **Слияние «берём большее».** | подтверждено: сброс отменяется, ошибки в словах теряются (ENG-01, ENG-02) | на новых уровнях добавятся новые немонотонные данные (черновики, попытки) — та же беда |
| L4 | **Ответ — перечень строк.** | 15 отвергнутых правильных ответов в A0–A1 (SYS-02) | в A2 ответы длиннее; перечни станут неуправляемыми |
| L5 | **Источник в задании — панель в треть окна.** | `.srcbox details.src[open] { max-height: 36vh }` | текст на 200–600 слов в такой панели не читается |
| L6 | **Шаги урока — линейный список закрытых заданий.** | типы шагов: слово, объяснение, выбор, ввод, пары, группы, сборка | нет разговора по шагам, направляемого и свободного письма, записи речи |
| L7 | **Число файлов озвучки.** | 3771 запись на A0–A1; предел Pages на бесплатном плане — 20 000 файлов на сайт (та же страница лимитов) | при той же плотности предел будет достигнут примерно к B1–B2 |
| L8 | **Три голоса Испании и синтез по фразам.** | `CAST`: 22 персонажа на трёх голосах с разной высотой | длинные монологи и «живая» речь B1+ синтезом по фразам звучат однообразно; нужны настоящие записи или материалы по лицензии |
| L9 | **Правило «только пройденные слова».** | `Lexicon` проверяет каждое слово урока | с B1 нужны неадаптированные тексты; правило превращается в «неизвестные слова — только со словариком» |
| L10 | **Навигация и открытие уроков — одна цепочка.** | `isOpen`: урок открыт, если пройден предыдущий; плитки уровней A0–C1 заданы в коде, C2 нет | нельзя начать с A2 по итогам диагностики; нет места входному тесту |
| L11 | **Один реестр навыков.** | `content/site/skills.yaml`, 102 навыка | к B2 — 500+ навыков в одном файле и в одной записи прогресса |
| L12 | **Тесты строят весь курс.** | `siteData()` собирает все уроки на каждый запуск | время тестов растёт линейно с числом уровней |

## 3. Что сделать до разработки A2

Порядок — по зависимости: сначала то, без чего пилотный юнит нельзя ни показать, ни проверить.

| № | Изменение | Закрывает | Объём | Примечание |
|---|---|---|---|---|
| P1 | **Разделить данные сайта**: ядро (оболочка, карта курса) + файл данных на уровень (`d/a0.json`, `d/a1.json`, `d/a2.json`) + книги и грамматика отдельными файлами; загрузка по требованию | L1 | M | режим `--fragment` для переносимой сборки сохранить; тест «ядро меньше 1,5 МБ» |
| P2 | **Синхронизация**: отметка сброса, время ответа у слова, номер схемы, отказ сервера старой записи | L3, ENG-01, 02, 12 | M | описано в плане работ A0–A1, этап 3.4 |
| P3 | **Прогресс по уровням**: ключи `site:<id>` (общее) и `site:<id>:A2` (уровень); компактный формат слов и навыков | L2 | M | миграция при чтении; старые записи не трогать |
| P4 | **Шаблоны и типы ответов** | L4, ENG-03, 04 | M | разворот при сборке — страница не меняется |
| P5 | **Вход в уровень**: диагностика, независимое открытие уровня, плитка C2 | L10 | S–M | итог диагностики — рекомендация, не замок |
| P6 | **Экран источника**: текст или диалог на весь экран с возвратом к заданию, запоминание места | L5 | S | для текстов 150–200 слов достаточно |
| P7 | **Блок `chat`** — разговор по шагам: реплика собеседника (звук) → ответ ученика (сборка или ввод по шаблону) → следующая реплика; в конце — весь разговор | L6 | M | нужен для пилота |
| P8 | **Блок `compose`** — направляемое письмо: поле на 2–5 фраз, проверка по признакам (обязательные конструкции, длина, слова-опоры, слова вне словаря), затем образец | L6 | M | без вердикта «неверно»; признаки задаёт автор |
| P9 | **Профиль ученика** и подстановки в задания; поля с проверкой по типу | SYS-12 | M | хранить в браузере |
| P10 | **Блок `order`** (расставить по порядку) и ряд-таблица вместо карточек для месяцев, чисел | SYS-10 | S | |
| P11 | **Линтеры содержания** и поле `evidence` | TST-01…06 | M | план работ, этап 4 |
| P12 | **Кнопка «Мой ответ тоже верный?»** и локальный список | ENG-07 | S | отправка автору — после P13 |

**Критерий готовности к пилоту:** собирается и проходит в браузере юнит с `chat`, `compose`, профилем и
длинным аудированием; страница ядра легче 1,5 МБ; сценарии сброса и слияния покрыты тестами.

## 4. Что желательно сделать перед B1

| № | Изменение | Зачем |
|---|---|---|
| Q1 | **Экран чтения**: текст 300–600 слов, словарик по нажатию (общий и свой для текста), пометки «не понял» | основа уроков B1; механизм словарика по слову уже есть (`lookup`) — расширить на словарь текста |
| Q2 | **Плеер длинной записи**: перемотка по отрезкам, скорость, расшифровка по кнопке, вопросы привязаны к отрезкам | аудирование 2–5 минут |
| Q3 | **Редактор свободного письма**: счётчик слов, черновик в браузере, чек-лист задания, отправка | письмо 120–250 слов |
| Q4 | **Обратная связь на письмо**: обработчик в боте на Cloudflare, который отправляет текст и критерии языковой модели и возвращает исправленный вариант, замечания и оценку по критериям | открытые ответы с B1. Условия: только для вошедших; дневной предел запросов; ключ — в секретах; текст ученика не хранить дольше ответа; в интерфейсе — «оценка автоматическая и может ошибаться» |
| Q5 | **«Отправить преподавателю»**: текст уходит ботом в чат проверки (у бота уже есть `TELEGRAM_REVIEW_CHAT_ID`), ответ возвращается ученику | человек в цикле без системы ролей и кабинетов |
| Q6 | **Запись своей речи** (в браузере, без отправки): прослушать себя после образца | тренировка без оценки |
| Q7 | **Словарик вместо запрета слов**: `allow` на уровне текста + обязательный перевод неизвестного слова | L9 |
| Q8 | **Сбор статистики ответов** (обезличенно, раз в день, с согласия) | находить плохие задания по данным, а не только вычиткой |
| Q9 | **Навыки по уровням** (`skills/a2.yaml`…), сборка тестов по уровням | L11, L12 |
| Q10 | **Хранилище звука**: перенос записей в объектное хранилище или объединение фраз диалога в один файл с метками времени | L7 |

## 5. Что понадобится только для B2–C2

- **Пометки в тексте** (выделить, подписать), сравнение двух вариантов текста (свой и исправленный).
- **Задания на переписывание** (другой регистр, сжатие вдвое) с показом образца и критериев.
- **Расшифровка устного ответа** и обратная связь по тексту расшифровки; сам звук оценивать не нужно.
- **Портфель работ ученика**: все его тексты с обратной связью — как свидетельство уровня вместо балла.
- **Подлинные материалы**: ссылки и встраивание видео и подкастов (раздел «Разбор видео» уже умеет ссылку
  и построчный разбор); вопрос прав на тексты и записи решается до разработки уровня.
- **Проверка человеком как услуга**: очередь работ, ответы, статус — имеет смысл, только когда появятся
  преподаватели, кроме автора.

## 6. Чего пока не делать

| Что | Почему |
|---|---|
| Переписывать сайт на новой основе или переходить на фреймворк | текущая архитектура стабильна (750 проходов без ошибок); все ограничения из раздела 2 снимаются точечно |
| Оценивать произношение баллами | нет надёжного способа в браузере; ложные отказы демотивируют сильнее, чем отсутствие задания |
| Разговорного собеседника на языковой модели в A2 | начинающему нужен предсказуемый образец; пробовать не раньше B1 и только как тренировку без оценки |
| Автоматический допуск на следующий уровень по оценке модели за письмо | нарушает принцип «не объявлять субъективный ответ неверным без надёжных критериев» |
| Систему ролей, кабинеты преподавателей, группы | нет преподавателей и учеников в таком числе; путь Q5 закрывает нужду |
| Мобильные приложения | сайт уже ставится на главный экран; выигрыша для обучения нет |
| Адаптивный подбор заданий по модели знаний | данных об учениках нет; сначала Q8 и простое правило «повторить слабый навык» |

## 7. Порядок и зависимости

```
A0–A1: правки содержания ──┐
P2 синхронизация ──────────┤
P4 шаблоны ответов ────────┼──► пилот A2-1 ──► проба на учениках ──► A2 ──► КТ A2
P1 разделение данных ──────┤        ▲
P7 chat, P8 compose, P9 ───┘        │
P5 вход в уровень, P6 экран источника, P10, P11, P12
                                     
A2 готов ──► Q1–Q3, Q7, Q9 ──► первые темы B1 ──► Q4–Q6, Q8, Q10 ──► B1 целиком ──► раздел 5 ──► B2
```

P1 и P2 можно делать параллельно с правками содержания A0–A1: они не зависят друг от друга. P7–P9 —
после P4 (ответы в `chat` и `compose` используют шаблоны).

**Риски платформы.** (1) Разделение данных меняет загрузку страницы — нужна проверка работы без сети после
первого захода (сейчас всё в одном файле и работает само). (2) Обработчик обратной связи — первые платные
вызовы и первые персональные тексты на сервере: нужны предел расходов и короткая политика хранения.
(3) Бесплатные лимиты Cloudflare (записи KV, число файлов) — проверить актуальные значения перед P3 и Q10.
