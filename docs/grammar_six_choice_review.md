# ТЗ №18: распределение шести и более вариантов

Проверены все 17 юнитов. После ТЗ №17 осталось 479 вопросов с полем `options`: 91 с двумя вариантами, 297 с тремя, 64 с четырьмя, 18 с пятью и 9 с шестью. Девять вопросов с шестью вариантами находятся в 7.1 (два) и 11.1 (семь). Кроме них сохраняются девять заданий с выбором слов в пропусках. Упражнение 6.4 остаётся ручным вводом по ТЗ №17: возвращать шесть кнопок в него не требуется.

## Найденные причины и исправления

1. Восстановление старой попытки без сохранённого плана подставляло исходный массив вариантов. Такие попытки не получали перемешивание новых попыток. Теперь план имеет собственную версию `choiceOrderVersion: 2`. При переносе сохраняются порядки уже показанных вопросов, включая текущий вопрос без ответа; ещё не открытые вопросы получают перемешанный план. Ответы, черновики, ошибки, статус, опыт и позиция не сбрасываются. Повторный перенос не меняет порядок.
2. Старое представление упражнения через форму могло обращаться к рендеру вариантов без созданной попытки. Теперь оно создаёт и сохраняет тот же план перед выводом вариантов; повторный рендер использует сохранённый порядок.
3. Контроль распределения включался только с восьми однотипных наборов. Поэтому семь вопросов с шестью вариантами в 11.1 могли оставаться сильно смещёнными. Контроль теперь начинается с `max(5, число вариантов)` вопросов; один и тот же порог используют генератор и автоматическая проверка. В серии из семи вопросов с шестью вариантами на одной позиции допускается не больше двух правильных ответов. Для очень коротких мини-проверок сохраняется случайность, без обязательной квоты каждой позиции.

Изменена общая логика; исходные варианты, правильные ответы и учебные материалы не переставлялись и не редактировались.

## Сохранённое поведение

План создаётся при запуске попытки и хранится вместе с ней. Проверка и цветовая индикация используют значения вариантов (`data-gvalue`, `data-gslot-value`), а не их экранные индексы. После ответа, возврата назад, перезагрузки, повторения ошибок и редактирования пропусков порядок сохраняется. Полное повторное прохождение создаёт новую попытку и новый план. Если в старой попытке уже показаны все вопросы, их порядок сохраняется; новый план появляется при следующем полном прохождении.

Педагогическое исключение `shuffleOptions: false` с обязательным `optionOrderReason` продолжает работать на уровне вопроса и упражнения. Для каждого оставшегося неприкреплённого набора перемешиваются и правильные ответы, и отвлекающие варианты. Система ошибок, исправлений, зелёный/жёлтый/красный статусы и звуки сохранены.

## Автоматические проверки распределения

- Для 2, 3, 4, 5, 6, 7, 8 и 10 вариантов: по 300 запусков упражнений из 30 вопросов. Во всех попытках проверяются допустимость перестановок, приблизительная равномерность, отсутствие длинных серий и простых циклов. Дополнительно проверяется совокупное распределение по запускам и достижимость каждой позиции каждым вопросом. Во входных массивах правильный ответ намеренно стоит последним.
- Для серии из семи вопросов с шестью вариантами: 300 запусков; ни одна позиция не содержит больше двух правильных ответов в попытке.
- Для всех девяти настоящих вопросов с шестью вариантами: по 600 запусков их полных упражнений, 5400 наблюдений. Каждая позиция достигается каждым вопросом. Совокупные количества по позициям: **842, 895, 843, 930, 942, 948**, при среднем 900. Доля шестой позиции — 17,6%, ожидаемая доля — 16,7%; отклонение не превышает установленный тестом допуск. Это воспроизводимый тест с фиксированными начальными значениями генератора, а не измерение пользовательских ответов. Подробности по юнитам и вопросам — `grammar_six_choice_audit.json`.
- Перенос старых исходных планов, текущий вопрос без ответа, повторная загрузка, повреждённые планы, сохранение ответов/ошибок, создание плана старой формой и полное повторное прохождение.
