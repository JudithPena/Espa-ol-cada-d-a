- Ошибки №1, №2: сохраняется соответственно две и одна жизнь, правильный ответ скрыт.
- Ошибка №3: ноль жизней, ученик остаётся на вопросе, подробное объяснение связано с конкретным вопросом.

- Для мобильных ширин дополнительно проверена уменьшенная до 520 px высота окна при фокусе в текстовых полях. **Настоящая клавиатура Android/iOS и её поведение не проверялись.**

## Блокировка слияния

GitHub REST API возвращает `mergeable: false`, `mergeable_state: dirty`: **есть конфликты слияния**.
Ветка PR и целевая ветка `claude/charming-cerf-bzze60` разошлись от общего предка `2bcd62c`: на момент проверки у PR 27 собственных коммитов, у целевой ветки 22 новых. Целевая ветка дополнительно изменила следующие файлы, присутствующие в PR:

- `espanol/grammar_player.js` — особенно важно: в целевой ветке есть альтернативная реализация `lastError`/`errorHistory`, `gRecoveryView`, ограничения мини-проверок и экрана разбора; нельзя механически принять одну из версий целиком.
- `espanol/site_template.html` — общая оболочка и CSS, включая книги и разбор ошибок.
- `tests/site_grammar.test.cjs` — тесты механики на всей грамматике.
- `docs/site_grammar_guide.md` — правила и описание новых юнитов.

Точные конфликтные hunks перед разрешением необходимо получить через реальный `git merge --no-commit` или `git rebase` в отдельной рабочей копии: одних сравнений GitHub недостаточно, чтобы утверждать список конфликтующих строк.

### Безопасный порядок

1. Сделать резервную ветку от текущего HEAD PR.
2. Обновить **только ветку PR**, не целевую ветку и не основной курс.
3. Вручную разрешить пересечения, **сохранив изменения целевой ветки по новым юнитам, книгам, `lastError`/`errorHistory` и новым тестам**, а также утверждённую для PR политику трёх жизней и добровольное возвращение к разбору. При необходимости адаптировать тесты к совмещённой логике, не менять содержание уроков.
4. Запустить весь CI, заново выполнить Playwright на четырёх ширинах, проверить `mergeable_state` и оставить PR открытым до решения владельца.

**Вердикт:** механика PR в собственном HEAD прошла браузерные проверки, **к слиянию PR пока не готов** из-за `dirty`-конфликтов. Нативная экранная клавиатура остаётся отдельным риском.
