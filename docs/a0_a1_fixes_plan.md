## 3. Единая модель: источник, правило, навык, порядок

Правки №1, 5, 6, 8 и 11 решаются одной моделью данных (только уроки сайта; разбор уроков канала не меняется):

- **id блока.** У источников (`dialogue`, `reading`, `mission`) и объяснений (`rule`, `tip`, `note`, `text`,
  `compare`, `table`, `list`, `examples`, `conjugation`) — необязательный `id`. Текстовые блоки получают
  словарную форму `{id, text}`.
- **Источник задания — только явный.** У задания (блок или отдельный вопрос, в том числе вопрос `quiz`):
  `source: <id>` — задание проверяет понимание этого источника; `free: true` — задание самостоятельное.
  Автоопределения «ближайшего диалога» нет: в перестроенном уроке каждое задание после источника обязано
  иметь одно из двух, иначе `validate` пишет ошибку. Привязка проверяется вручную по карте слайдов.
- **Правило.** `rule: <id>` (или `rule: none`). Без него — ближайшее объяснение того же витка (виток
  кончается на `learn`, `header`, `dialogue`, `reading`, `mission`, `review`); нет объяснения — нет ссылки.
- **Навык.** `skill: <тег>` из реестра `content/site/skills.yaml` (название, урок введения, объяснение).
  Нужен для интервального повторения конструкций и для сильных/слабых тем в контроле.
- **Порядок и экраны.** Порядок блоков в YAML — порядок шагов. Объяснения, примеры и картинки, идущие подряд
  между заданиями, — один экран; новый экран — с `slide: new`. Автодобавок нет: проверка непроверенных слов —
  блок `recap`, запланированное повторение — блок `review`, оба там, где их поставил автор по карте.
- **Версия и проверка.** У урока `version` (по умолчанию 1; перестроенные уроки — 2) и `check: control | soft`.

Ссылки разрешаются при сборке (`espanol/site.py`) в индексы блоков урока, поэтому работают и в повторении,
где задания берутся из разных уроков.

## 4. Критерии проверки (№4)

Тренировка: ошибки, подсказки и исправления не наказываются, итог задания — по фактическому результату.

Контроль (`check: control` — итог A0 `familia/repaso` и итог A1 `final/examen`; `check: soft` — тесты тем):

| Исход задания | Балл |
|---|---|
| решено с первой попытки | 1 |
| ученик сам исправил ошибку (вторая попытка ввода, лишняя плитка, неверная пара) | 0,5 |
| решено с подсказкой (плитка, первые буквы, текст скрытого аудио) | 0,25 |
| ответ показан системой или задание не решено | 0 |

Порог — **80 %** от максимума. Почему так: 80 % — принятый порог освоения в mastery learning (Блум,
«уровень освоения» 80–90 %); ниже — признак того, что пробелы есть хотя бы в одной из четырёх-шести тем
итога. Частичный балл за самоисправление признаёт, что ученик знает правило, но ещё не автоматизировал его,
и не даёт сдать контроль одними исправлениями (все задания со второй попытки — 50 %). Подсказка стоит
меньше, потому что часть ответа показана.

Не сдан `control` — урок не засчитывается, следующий урок закрыт с объяснением, показаны слабые темы
со ссылками на уроки и «Пройти ещё раз»; пройденные уроки открыты всегда. Не сдан `soft` — честный
жёлтый итог «нужно повторить» и те же ссылки, но следующий урок открыт (решение автора).

## 5. Звук (№2) — решение автора

У каждого задания на слух есть «Нет возможности слушать»: альтернатива на остаток урока (её можно выключить).
Авторская альтернатива (`noaudio`) проверяет ту же цель письменно (число по записи словами, время по тексту);
без неё задание откладывается «до звука» и не оценивается. Урок, пройденный так, засчитывается с пометкой
«без звука»; аудирование не подтверждено и остаётся в повторении. При ошибке загрузки — статус
«Не удалось включить звук» и «Попробовать снова». Ноль оценённых заданий не даёт ни 100 %, ни прохождения.

## 6. Версии и прогресс (№3)

`P.done` (порядок открытия, звёзды, опыт) не меняется. Новая версия подтверждается в `P.ver[id] = {v, …}`;
запись без версии считается версией 1, поэтому миграция ничего не переписывает и идемпотентна.
Карта курса предлагает «Урок обновлён — пройти новую версию», «Что вы уже умеете» показывает только
подтверждённые цели. `mergeProgress` объединяет `P.ver`, `P.skills`, `P.ctl` («взять большее»), сервер
хранит JSON как есть.

## 7. Порядок работ и критерии готовности

1. **Этап B — движок** (по группам, с тестами): поток урока; источник в задании и повтор рядом с ним;
   итог задания; ввод и подсказки; правило; звук; версии; повторение конструкций; контроль.
2. **Этап C — темы 00 → 23 по одной:** карта экранов каждого урока → аудит → ручная правка YAML
   (`source`/`free`, `rule`, `skill`, `mistakes`, `noaudio`, `recap`, `review`, формат `write`, `version: 2`)
   → проверка связей → Playwright 320/390/430 px → validate, pytest, node → коммит и push.
3. **Этап D** — полный прогон, документы, отчёт `docs/a0_a1_fixes_report.md`, проверка CI.

Тема готова, если: у каждого урока есть карта, и её сигнатура совпадает с шагами движка; ни одно задание
после источника не стоит без `source`/`free`; ссылки на правила проверены вручную; навыки размечены;
`write` с понятным форматом и естественными вариантами; validate, pytest и node зелёные; урок пройден
в браузере на трёх ширинах с ошибкой, повтором, источником и без звука.
